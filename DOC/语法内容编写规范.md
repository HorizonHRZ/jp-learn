# 语法内容编写规范（给批量写内容的人/程序看）

> 这份文件是 `tools/gen-grammar.mjs` 的**配套规范**。写成文件是因为
> 内容要分很多批写，每批的规矩必须完全一样 —— 靠"记在脑子里"一定会漂。
> 每次写完，用 `gen-grammar.mjs` 的自检来验收（它会精确指出哪条的哪个字段不合格）。

## 一、产出物长什么样

一个内容文件 = 一个 `.mjs`，放在 `tools/` 下，形如 `内容-JLPT-N1x.mjs`：

```js
export default {
  level: 'N1',            // 整个文件必须同一个等级
  source: '项目自编',      // 来源，如实写
  line: 'jlpt',           // 'jlpt' = 应试线；'written' = 书面语线
  items: [
    {
      id: 'n1-j-<小写罗马字slug>',
      level: 'N1',
      category: '条件',
      title: '〜ものなら：要是能…的话（可惜做不到）',
      connection: '动词可能形 + ものなら（也说 もんなら）',
      meaning: '……两三句白话解释，说清"什么时候用它、它比近义说法多了什么意味"……',
      examples: [
        { ja: 'できるものなら、世界一周したい。', zh: '要是能做到的话，真想环游世界。', note: '愿望，暗含很难' },
      ],
      mistakes: [
        '用在"容易做到"的事上 → 它必须带"很难、几乎做不到"的意味',
      ],
      confusions: [
        {
          with: 'ものなら 与 なら',
          diff: 'なら 是中性条件；ものなら 前面必须接可能形，且带"很难实现"的感叹。',
          example: { ja: '行くなら教えて／行けるものなら行きたい', zh: '要去的话告诉我／要是能去真想去' },
        },
      ],
      tags: ['N1', '条件', 'ものなら', 'mononara', '要是能'],
    },
  ],
};
```

## 二、字段规则（`gen-grammar.mjs` 会逐条查，不合格直接不生成）

| 字段 | 要求 |
|---|---|
| `id` | 只能小写字母、数字、连字符。**全库唯一**。应试线用 `n<等级>-j-<slug>` |
| `level` | 同文件统一。只写 `N5 N4 N3 N2 N1` |
| `category` | 必填。用现有取值（见第四节），不要自己造 |
| `title` | 必填。形如「〜句型：中文意思」。「〜」用全角波浪 |
| `connection` | 必填。写清接续：前面接什么形 |
| `meaning` | 必填。**说清用法和语感**，不要只翻译 |
| `examples` | 必填，≥ 4 条。每条要有 `ja` 和 `zh`；`ja` **绝对不能有 ASCII 空格**（会让分词退化成逐字）；`note` 可选 |
| `mistakes` | 必填。**字符串数组**（不是对象）。写学习者真会犯的错，格式「错误做法 → 为什么错」 |
| `confusions` | 可选但强烈建议 2 条。每项要 `with` + `diff`；`example` 可选 |
| `tags` | 必填。见第三节 |

## 三、`tags` 的硬规矩（这几条都是踩坑换来的）

1. **标题里有汉字的，tags 必须补假名读音**。
   例：标题「相まって」→ tags 要有 `あいまって`。
   原因：初学者敲的是假名，搜「あいまって」原来 0 条。
2. **多字标题要补"带空格"和"不带空格"两种写法**。
   例：`は が`、`はが`、`は と が`、`はとが`。
   原因：语法书写法「は と が の違い」是初学者最自然的输入。
3. **补常见别称**。例：`四大假定`、`四个假定`、`四大仮定`。
4. 第一条 tag 写等级（`N1`），第二条写 category。

## 四、可用的 `category` 取值（用现成的，别造新的）

`时态 接续 助词 惯用型 推量 条件 逆接 让步 愿望 可能 使役 受身 授受 敬语
时间 理由 评价 归纳 指示 副词 接续词 终助词 存在 读法 书面语 文语`

> 判断顺序：是句型/惯用就选「惯用型」；讲接续规则选「接续」；
> 讲某个助词的用法选「助词」；书面语体选「书面语」；文语（古文残留）选「文语」。

## 五、文案禁区（会被自检拦下）

- **不许有 Markdown**：`**`、反引号、`[文字](链接)` 都不行。
  这些字走 `textContent`，会原样把星号显示给用户。
- **中文讲解里不许出现两个以上连续英文字母**（`A`/`B` 这种单字母对比可以，
  但 `N1` 也不行 —— 写「一级」或干脆不写）。
- 例句里不许有 ASCII 空格、制表符。

## 六、内容质量要求（自检查不出来，但这是重点）

- **例句要像真会出现的句子**，不要「これはペンです」这种造句感。
  优先用能体现该句型语感的场景。
- **`mistakes` 要写"为什么错"**，不是重复 `connection`。
- **`confusions` 要写"判断点"** —— 让读者能用一句话决定该用哪个。
- **不要写自己不确信的内容**。宁可少写一条，也不要编一个错的接续。

## 七、怎么跑

```powershell
# 在 jp-learn 目录下
node tools\gen-grammar.mjs tools\内容-JLPT-N1x.mjs
node tools\build-grammar-index.mjs
node tools\test-grammar.mjs
node tools\check-grammar-dup.mjs
```

`gen-grammar.mjs` 是**增量合并**：同一个 id 已存在时只合并 `tags`/`alias`，不覆盖正文。
所以反复跑是安全的；新条目直接追加。
